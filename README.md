# מרדכי ווינרים

אפליקציית משחקי תחזיות פרטית. היתרה וירטואלית בלבד, ללא הפקדות או משיכות.

אפליקציה: https://dvircos.github.io/dmw/

## מקורות נתונים – הפרדה מחייבת

- **SportStatsAPI בלבד** משמש לייבוא משחקים, סטטוסים ותוצאות.
- **Winner בלבד** הוא מקור יחסי ההימור. התוסף קולט 1X2 וכן שווקי הפרשי שערים, מעל/מתחת 2.5 ו-BTTS מכל ליגות הכדורגל הזמינות ב-Winner; SportStatsAPI לעולם אינו מספק או משנה יחסים.
- Supabase הוא מסד הנתונים וה־RPC של האפליקציה, לא ספק נתוני כדורגל.
- אין שימוש ב־RapidAPI / Free API Live או API-Football / API-Sports. האינטגרציות הישנות הוסרו.

## סנכרון משחקים

- GitHub Actions מפעיל ייבוא אוטומטי **בכל יום בשעה 06:00 לפי שעון ישראל**.
- הייבוא מבקש מ־SportStatsAPI משחקים משבעת הימים הקרובים, בכל הליגות המוגדרות ב־`sync_sportstats.py`.
- בגלל מעבר שעון קיץ/חורף, ה־Workflow מופעל ב־03:00 וב־04:00 UTC; הקוד בודק את השעה המקומית ומבצע ייבוא רק בהרצה שמקבילה ל־06:00 בישראל.
- אפשר להפעיל ייבוא ידני דרך Actions עם חלון של 1–7 ימים.
- כל בקשת ספק מחויבת קודם במכסת `reserve_api_requests`. אין retries, pagination או קריאות פר־משחק.
- ייבוא משחקים מקבל רק משחקים בסטטוס NS/TBD. הוא אינו משנה יחסי Winner, הימורים, יתרות או מזהי משחק פנימיים.

## סנכרון תוצאות

- סנכרון תוצאות מתבצע בארבע השעות המקומיות 21:00, 22:00, 23:00 ו־00:00.
- נבדקים רק משחקים שעבר מועד הפתיחה שלהם, שטרם אושרה בהם תוצאה ושממופים למזהה SportStatsAPI.
- מתבצעת לכל היותר בקשת רשימת משחקים אחת לכל ליגה רלוונטית.
- רק `status = FT` יחד עם `status_code = final` מתקבלים כתוצאה סופית. AET/PEN אינם מוכרעים, כדי לא לכלול הארכה או דו־קרב פנדלים.
- RPC ייעודי `sync_sportstats_result` מעדכן לפי מזהה SportStatsAPI טקסטואלי ומכריע הימורים בודדים ומשולבים באופן טרנזקציוני.
- תהליך התוצאות אינו משנה `fixture_id`, מזהי משחק, יחסי Winner או `odds_locked`.

## הגדרת GitHub Actions

יש להגדיר את ה־Secrets הבאים:
- `SPORTSTATS_API_KEY`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

אין צורך ב־`API_KEY` של ספק כדורגל אחר.

## יחסי Winner

תוסף Winner פועל בנפרד מסנכרון המשחקים והתוצאות. הוא קורא את יחסי 1X2 שמוצגים באתר Winner ושולח רק את היחסים ל־Supabase. הוא אינו יוצר משחקים, אינו מביא תוצאות ואינו פונה לספק נתוני כדורגל.

## בדיקות ותחזוקה

- בדיקות Python: `python -m unittest discover -s tests -v`
- בדיקת תחביר: `python -m py_compile sync_sportstats.py team_utils.py`
- סנכרון ידני: `python sync_sportstats.py fixtures --days 7`
- סנכרון תוצאות ידני: `python sync_sportstats.py results`

יש להריץ את המיגרציות הקיימות ב־Supabase לפי מצב הפרויקט. אין להריץ מחדש את סכמת הבסיס על מסד נתונים פעיל ללא בדיקת ההשפעה.


## שווקי Winner דינמיים
- התוסף אינו מסנן לפי ליגה ומזהה את שווקי הכדורגל מכל הליגות שמופיעות בפיד Winner. הוא משייך אותם רק למשחקים שכבר קיימים באפליקציה.
- קטלוג המשחקים באפליקציה נשאר כרגע בחמש התחרויות שהוגדרו לייבוא SportStatsAPI: פרמייר ליג, לה ליגה, ליגת העל, ליגת האומות וליגת האלופות. הוספת ליגות נוספות מחייבת להוסיף גם את מזהי הליגות לסנכרון המשחקים.
- השווקים הנתמכים כעת: 1X2, הפרשי שערים (הימור יתרון מלא), מעל/מתחת 2.5 שערים, ושתי הקבוצות יבקיעו.
- האפליקציה מציגה משחק ככרטיס נפתח; בתוך הכרטיס מוצגים רק השווקים שהתקבלו בפועל ושמנהל המערכת הפעיל.
- מנהל המערכת יכול להפעיל/להסתיר כל סוג שוק במסך הניהול. ההגדרה גלובלית לכל המשחקים.
- יש להריץ פעם אחת את `migration_dynamic_winner_markets.sql` ב-Supabase SQL Editor. המיגרציה מוסיפה טבלאות, הגדרות מנהל, קליטת שווקים, הימורים בודדים וסגירת הימורים לפי תוצאת 90 דקות.
- שווקים דינמיים כרגע נתמכים כהימורים בודדים. טופסי קומבינציה נשארים במסלול 1X2 הקיים.


## הימורים משולבים עם שווקי Winner
- ניתן לצרף לאותו טופס עד 8 משחקים, כאשר בכל משחק בוחרים שוק אחד: 1X2, הפרשי שערים, מעל/מתחת 2.5 או BTTS.
- לחיצה על יחס מוסיפה אותו לטופס המשולב; בחירה אחרת מאותו משחק מחליפה את הבחירה הקודמת.
- המחיר נבדק שוב בשרת בזמן שליחת הטופס; אין הסתמכות על יחס שהדפדפן שולח.
- שווקי BTTS, סך שערים והפרשי שערים נסגרים לפי תוצאה מאושרת של 90 דקות. ביטול משחק מבטל את הרגל ומחשב מחדש את הטופס.
- המיגרציה לפריסת התמיכה בטפסים מעורבים נמצאת ב-`migration_market_parlay_support.sql`.
